# إدارة موظفي الطابور والإسناد التلقائي

يوثّق هذا الملف تصميم إدارة موظفي الرصد في MIP: حالات التوفر، تسجيل ساعات العمل، إعدادات الطابور لكل موظف، ومحرك الإسناد التلقائي. الكود في `apps/api/src/modules/queue/workforce.ts` و`workforce.routes.ts`، والترحيل `packages/db/migrations/0040_queue_workforce.sql`.

## 1. البنية

```
المتصفح (الموظف)            API                                   PostgreSQL
 ├─ اختيار الحالة  ───────▶ POST /workforce/status ──┐            agent_status_periods (سجل الفترات)
 ├─ نبضة كل 60 ث  ───────▶ POST /workforce/heartbeat │            agent_presence (آخر نبضة)
 └─ إغلاق/تصعيد   ───────▶ POST /queue/items/:id/…  ├─▶ معاملة ─▶ queue_items / queue_events
                                                     │
                                  بعد الالتزام ──────┴─▶ runAssignmentPass()  ◀── قفل استشاري واحد
عامل workforce (كل 20 ث): sweepStatuses() ثم runAssignmentPass()   (مسار التعافي)
```

- **لا إسناد في المتصفح.** كل إسناد تلقائي يحدث في الخادم داخل معاملة.
- **مصدر الحقيقة سجل الفترات**، لا إجماليات مخزنة. كل رقم في التقارير يُحسب من الفترات ويمكن تتبعه إلى صفوفها.

## 2. الجداول الجديدة (ترحيل 0040 — إضافي فقط)

| الجدول / العمود | الغرض |
|---|---|
| `agent_status_periods` | فترة لكل حالة: `user_id`، `status`، `previous_status`، `started_at`، `ended_at` (NULL = الحالية)، `source` (agent/supervisor/system)، `actor_id`، `reason`، `end_source`، `end_reason`، `duration_seconds` (محسوب)، `corrected_count`. فهرس فريد: فترة مفتوحة واحدة لكل موظف. |
| `agent_presence` | آخر نبضة من جلسة الموظف. |
| `agent_status_corrections` | كل تصحيح من المشرف: القيم قبل وبعد والسبب. إلحاقي فقط. |
| `team_queue_defaults` | الافتراضي لكل فريق. |
| `agent_queue_settings` | التخصيص لكل موظف. NULL = موروث. |
| `queue_items.priority` | `normal` (افتراضي) أو `high`. يضبطها المشرف فقط. |
| `queue_events.event_type` | أُضيفت القيمة `priority_changed` (توسيع للقيد، لا تضييق). |
| الصلاحية `workforce:correct` | تصحيح سجلات الحالات. للمدير افتراضياً، ولغيره بمنح فردي. |
| الإعدادات | `queue.auto_assign_enabled` (**false**)، `queue.lane_order`، `queue.starvation_minutes` (45)، `queue.default_max_open` (5)، `workforce.heartbeat_timeout_minutes` (10)، `workforce.max_status_hours` (12)، `workforce.operational_statuses` (["available"]). |

**الحماية على مستوى القاعدة:** مُشغّل (trigger) يمنع حذف الفترات أو تعديلها. المسموح فقط: إغلاق الفترة المفتوحة مرة واحدة، أو تعديل عبر مسار التصحيح الذي يفعّل `mip.status_correction` لمعاملته وحدها. جدول التصحيحات إلحاقي.

الترحيل لا يعدّل ولا يحذف أي صف موجود. اختبار الترقية (`upgrade-0036.itest.ts`) يطبّق 0036→0040 على قاعدة بشكل الإنتاج، ويتحقق أن بصمة صفوف الطابور والأحداث والملاحظات والعضويات والمستخدمين لم تتغير.

## 3. إلغاء «بدء المعالجة»

- الإجراء `start` أُزيل (المسار يعيد 404). يبدأ وقت العنصر في الصندوق من `assigned_at` الذي يسجّله الخادم.
- الإغلاق (مع مراجعة تصنيف الذكاء الاصطناعي) والتصعيد ممكنان مباشرة من `assigned`.
- إعادة الفتح تعيد العنصر `assigned` للمسند إليه نفسه بوقت إسناد جديد، أو `new` إن لم يعد في الفريق.
- **التوافق مع البيانات السابقة:** عناصر `in_progress` الموجودة وأحداث `started` تبقى كما هي، وتُعامل كعمل مفتوح في الصندوق مثل `assigned`. عمودا `started_at` و`first_started_at` محفوظان للتاريخ. `queue_reviews.started_at` يبقى NULL في الدورات الجديدة.
- المؤشر القديم «زمن المعالجة» (الإغلاق − البدء) استُبدل بـ **«من الإسناد حتى الإغلاق»**، ولا يُسمّى AHT.

## 4. حالات الموظفين وسياسة الجلسات

الحالات: متاح، استراحة، خارج المكتب، اجتماع، تدريب، غير متصل. **«متاح» وحدها تستقبل الإسناد التلقائي.**

| الحدث | النتيجة | المصدر |
|---|---|---|
| تسجيل الدخول، فتح المتصفح، النبضة | **لا يبدأ أي حالة** (يبقى غير متصل) | — |
| اختيار الموظف لحالة | تُغلق الفترة الحالية وتُفتح الجديدة بنفس اللحظة (لا فجوة ولا تداخل) | agent |
| اختيار الحالة نفسها مرة أخرى | لا تغيير (آمن مع إعادة المحاولة والنقر المزدوج) | — |
| المشرف يغيّر حالة موظف في نطاقه | سبب إلزامي + سجل تدقيق | supervisor |
| انقطاع النبضة أكثر من `heartbeat_timeout_minutes` | تنتهي الحالة **عند آخر نبضة**، لا عند لحظة الفحص، وتُفتح «غير متصل» | system + سبب |
| حالة أطول من `max_status_hours` (نهاية دوام غير مسجلة) | تنتهي عند الحد الأقصى | system + سبب |
| تعطيل الحساب | تنتهي فوراً | system + سبب |
| تسجيل الخروج | «غير متصل» | agent |

- الصناديق لا تُفرَّغ تلقائياً عند الاستراحة أو الانقطاع. العمل يبقى مع صاحبه، ويعيد المشرف توزيعه بقرار صريح (إعادة التوزيع: سبب إلزامي، حدث `unassigned` لكل عنصر، وسجل تدقيق).
- **التصحيح:** للفترات المنتهية فقط، بصلاحية `workforce:correct` وضمن نطاق المشرف. السبب إلزامي، ويُرفض أي تداخل مع فترة أخرى أو نهاية في المستقبل. القيم قبل وبعد تُحفظ في `agent_status_corrections` وفي `audit_log`.

## 5. تسجيل ساعات العمل

- التخزين UTC (`timestamptz`) بساعة الخادم، والعرض والتقارير بتوقيت `Asia/Riyadh`.
- `statusTime(users, from, to)`: الثواني لكل موظف ويوم وحالة. تُقص الفترة على حدود النافذة، وعلى «الآن» للفترة المفتوحة، وتُقسم الفترة العابرة لمنتصف الليل بين اليومين بالرياض. لا يُحسب شيء مرتين ولا يسقط شيء (مختبر).
- `timeTotals`: لكل حالة، إضافة إلى:
  - **المسجل في النظام**: كل الحالات عدا «غير متصل».
  - **وقت العمل التشغيلي**: الحالات المذكورة في `workforce.operational_statuses` (قابل للضبط، و«غير متصل» ممنوع).
- **ما لا تخلطه:** هذا وقت حضور في النظام. ساعات الدوام المجدولة غير ممثلة في النظام بعد. الإنتاجية (الإغلاقات والمدد) تُحسب من أحداث الطابور، لا من الحضور.
- التقارير اليومية والأسبوعية والشهرية: `GET /workforce/time` يعيد صفوفاً يومية جاهزة للتجميع.

## 6. إعدادات الطابور لكل موظف

ترتيب الوراثة: **الموظف ← الفريق ← النظام.** NULL يعني موروث، والمصفوفة الفارغة تعني «لا شيء مسموح». الشاشة تُظهر مصدر كل قيمة («مخصص للموظف» / «موروث من الفريق» / «افتراضي النظام»).

الحقول: البرامج (من برامج الفريق فقط، ويُرفض غيرها)، أنواع التفاعلات (intent)، المسارات، الحد الأعلى للصندوق، الإسناد التلقائي، استقبال الأولوية العالية. الصفحة تعرض أيضاً الفريق والحالة الحالية وعدد المفتوح. كل حفظ يُسجَّل في `audit_log` بقيمه القديمة والجديدة، ثم تُشغَّل محاولة إسناد فوراً.

## 7. محرك الإسناد التلقائي

**الأهلية:** حساب نشط بدور موظف رصد يملك `queue:work`، وعضو نشط في فريق العنصر، وحالته «متاح»، والإسناد التلقائي مفعّل له، وصندوقه أقل من حده. ويجب أن يكون برنامج العنصر ونوعه (لا ينطبق على القصص) ومساره مسموحاً له، وألا يكون العنصر عالي الأولوية إن كان الموظف لا يستقبلها. وتشمل الأهلية فقط عناصر `new` غير المدموجة، وليست تفاعلات داخل قصة.

**السعة:** تُحسب العناصر `assigned` و`in_progress`. المصعّد ينتظر المشرف ولا يشغل مكاناً في الصندوق.

**الترتيب:**
1. أولوية عالية.
2. ما انتظر `starvation_minutes` فأكثر، الأقدم أولاً (منع التجويع).
3. ترتيب المسارات (القصص ← المؤثرون ← العام افتراضياً، قابل للضبط).
4. الأقدم انتظاراً.

بين الموظفين: الأقل عبئاً أولاً، ثم الأطول انتظاراً منذ آخر إسناد.

**المحفّزات** (بعد التزام العملية الأصلية): التحول إلى متاح، وصول عنصر (استقبال آلي أو إضافة يدوية)، الإغلاق، التصعيد، إلغاء الإسناد، إعادة الفتح إلى الطابور، الإسناد اليدوي أو إعادة الإسناد، النقل لفريق آخر، تغيير الأولوية، تغيير الإعدادات أو السياسة، إعادة التوزيع. ويعمل كذلك مرور دوري كل 20 ثانية.

**الأمان مع التزامن:**
- **قفل استشاري واحد** (`pg_advisory_xact_lock('mip:queue-assign')`) يسلسل كل مرور من الـ API والعامل، فلا يُسند عنصر مرتين ولا يتجاوز صندوق حده بسبب سباق.
- كل إسناد **CAS على النسخة** من الحالة `new`. المرور المعاد لا يجد ما يكرره، فالعملية idempotent.
- المرور **معاملة واحدة**: الفشل يتراجع والعناصر تبقى غير مسندة. فشل المرور بعد العملية الأصلية لا يلغيها، والمرور الدوري يستعيد ما فات.
- `FOR UPDATE SKIP LOCKED` على العنصر المختار.
- اختبار: 8 مرورات متزامنة مع تغييرات حالة متزامنة، 4 موظفين × حد 3. النتيجة 12 إسناداً بالضبط، وحدث `assigned` واحد لكل عنصر.

**الإسناد اليدوي** من المشرف مسموح لموظف غير متاح أو صندوقه ممتلئ (قرار بشري)، ويُسجَّل `metadata.override` في الحدث، وتنبّه الواجهة قبل التنفيذ. الإسناد التلقائي لا يتجاوز الحد أبداً.

## 8. المسارات الثلاثة

- **الرصد العام:** قواعد الأهلية القائمة دون تغيير (استفسار أو شكوى ذات صلة، مع الاستثناءات).
- **المؤثرون:** آلية الاكتشاف القائمة. منشور واحد = عنصر واحد (فهرس فريد على `post_id`). تغيّر التصنيف إلى مؤثر ينقل المسار عبر `reconcileSections` مع حدث `section_changed`، دون تغيير هوية العنصر أو صاحبه أو سجله.
- **القصص:** القصص المعتمدة فقط (`state <> 'candidate'`). القصة وحدة عمل واحدة، ومنشوراتها تبقى مرتبطة ولا تصبح مهام منفصلة. الدمج يحفظ الملاحظات والسجل والإسناد (القائم منذ 0036).

لم يتغير منطق جمع X ولا تصنيف الذكاء الاصطناعي.

## 9. مؤشرات الأداء

| المؤشر | التعريف | الإسناد عند النقل |
|---|---|---|
| Queue Wait Time | الدخول ← أول إسناد | لصاحب أول إسناد |
| Assignment-to-Close Time | إسناد من أغلق ← الإغلاق (`queue_reviews.assigned_at`) | النقل وإعادة الإسناد يعيدان الساعة للمستلم، فلا يُنسب وقت السابق للاحق |
| Open Item Age | الآن ← الإسناد الحالي | لصاحبه الحالي |
| Completed Count | دورات المراجعة المغلقة، والعناصر دون تكرار | لمن أغلق فقط |
| Reopened Count | إعادة فتح عمل كان مع الموظف عند إغلاقه | `from_assignee` |
| Escalated Count | تصعيدات رفعها الموظف | `actor_id` |
| Current Box Occupancy | المفتوح / الحد الفعلي | — |
| Available / Break / Meeting / Training / Away Time | من سجل الفترات | — |

## 10. الواجهات

- **الموظف** (`/queue` لمن لا يملك صلاحية الإشراف): صندوقي، المغلقة، أدائي. مرشحات المسار والبرنامج والنوع. شريط بالحالة ومدتها، وسعة الصندوق، وما أُنجز اليوم. البطاقة تعرض المسار والأولوية والبرنامج والنوع والتصنيف والمدة منذ الإسناد. **لا زر بدء.**
- **مفتاح الحالة** في الشريط العلوي لكل من يملك `queue:work`، مع النبضة.
- **لوحة الفرق** `/queue/board`: الموظفون وحالاتهم ومددها، الصناديق وحدودها، المصعّد، المغلق اليوم، المنتظر والمتأخر، التوزيع حسب المسار والبرنامج، والوقت حسب الحالة. فيها تغيير الحالة بسبب، وإعادة التوزيع، وسجل الفترات مع التصحيح.
- **الإعدادات** `/queue/settings`: سياسة النظام، الافتراضي لكل فريق، والتخصيص لكل موظف.

الصور في `docs/queue-workforce/`.

## 11. التفعيل

1. تطبيق 0040 (إضافي فقط).
2. ضبط افتراضيات الفرق وحدود الصناديق.
3. يختار الموظفون «متاح».
4. يفعّل مدير النظام `queue.auto_assign_enabled` من صفحة الإعدادات. **التفعيل يوزّع فوراً العناصر المنتظرة حالياً.**
